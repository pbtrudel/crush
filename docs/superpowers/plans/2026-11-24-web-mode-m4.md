**What "theme" and "detach" mean in the browser.** The TUI "Themes" dialog
picks a terminal palette (`options.tui.active_theme`, Charmtone Pantera and
others). Spec 3.2 fixes the browser palette (the Holodeck tokens) and says
magenta is attention only, so a TUI theme cannot be mapped onto the browser
without breaking the token rules and the contrast checks of 3.11. The
browser theme is therefore its own setting with two values that keep every
token: `holodeck` (the spec 3.2 look) and `solid` (glass solid
`oklch(0.16 0.05 265 / 0.94)` on every glass panel, no backdrop blur, no
scan lines; for legibility and weak GPUs). The TUI has no "detach"
command; `rg -i detach internal/ui` finds only subagent wording. Spec 2.6
lists `POST /detach` in the system group. This plan reads detach as "stop
web mode from the browser": the gateway shuts down, every tab shows
"Session ended", the token dies, the terminal keeps running and `/web`
starts a new gateway with a new token. Both readings are planner decisions
1 and 2.

**Why visual settings live in the config.** Browser storage is keyed by
origin, and the origin carries the gateway's random port, so every
`localStorage` preference (motion, low power) is lost on each `crush` run
today (`web/src/state/motion.ts` stores `crush-web-motion` per origin). The
M3 carry "config set and remove for the visual settings only" fixes it: the
settings live in `options.web_display` in the global config, written
through an allowlist, and `localStorage` stays as the per-tab cache.

# Part A: M4a (security, secure prompts and sign-in)

### Task A1: Header-based auth for every API route and the stream (wire contract: browser)

Spec 2.3 threat model: "browser cookies are not isolated by port, so the
tab's cookie is sent to other `127.0.0.1` ports". The fix is to stop using a
cookie. The page keeps the token in `sessionStorage` (isolated by origin,
which includes the port), sends it as `Authorization: Bearer <token>` on
every fetch, and offers it to the stream as a WebSocket subprotocol, because
a browser cannot set headers on a WebSocket. `POST /api/auth` stays as the
token check the page runs before it stores the token. This task also closes
M3 deferred item 31 (row 2 of this plan's disposition table: no
foreign-Origin WebSocket upgrade test), and changes the 401 page text per
lead ruling 5: a new tab needs a fresh link from `/web`.

**Files:**
- Modify: `internal/web/auth.go` (`requireAuth`, `handleAuth`, remove `cookieNamePrefix`), `internal/web/gateway.go` (`Gateway.cookieName` field and its init in `Start`), `internal/web/stream.go` (`handleStream`: `websocket.Accept` options)
- Modify: `internal/web/auth_test.go` (`authedClient`, `staticJar`, `TestAPIRequiresCookie`, `TestTwoGatewaysKeepTheirOwnCookies`, `TestEveryRouteRequiresTheCookie`, `TestMissingCookieWithForeignOriginIsForbidden`), `internal/web/stream_test.go` (`dialStream`, `TestStreamRequiresCookie`); find any other cookie use with `grep -rn 'cookieName\|Cookie' internal/web`
- Create: `web/src/state/token.ts`, `web/src/state/token.test.ts`
- Modify: `web/src/api/http.ts` (`call`, `api.health`), `web/src/api/stream.ts` (`StreamEnv.WebSocket`, the `new env.WebSocket(...)` call), `web/src/state/store.ts` (`boot`), `web/src/api/http.test.ts`, `web/src/api/stream.test.ts`, `web/src/state/store.test.ts`
- Modify: `web/src/ui/Unauthorized.tsx` (the paragraph text), `web/e2e/smoke.spec.ts` (`a tab without the token is not linked` also asserts the new text)

**Interfaces:**
- Wire contract (browser):
  - Every `/api/*` route except `POST /api/auth` requires `Authorization: Bearer <token>` (constant-time compare). Missing or wrong: 401 `unauthorized` "missing or invalid token". A token in a query string is ignored (still 401).
  - `GET /api/stream` requires the subprotocol list to contain `crush.v1` and `crush.auth.<token>`; the answer selects `crush.v1`. Missing or wrong token: 401 before the upgrade. Foreign `Origin`: 403 `forbidden_origin` before the upgrade, with or without a valid token.
  - `POST /api/auth` body `{"token": string}` answers 204 with no `Set-Cookie`, or 401.
- Produces (Go): `const streamProtocol = "crush.v1"`, `const authProtocolPrefix = "crush.auth."`, `func requestToken(r *http.Request) string` (bearer header, or for a WebSocket upgrade the `crush.auth.` subprotocol entry).
- Produces (TS, `web/src/state/token.ts`): `export function token(): string | null`, `export function setToken(t: string): void`, `export function forgetToken(): void`. `http.ts` exports `authHeaders(): Record<string, string>` used by `call` and `health`. `stream.ts` `StreamEnv.WebSocket` becomes `new (url: string, protocols: string[]) => SocketLike` and `streamProtocols(): string[]` returns `['crush.v1']`, plus `'crush.auth.' + token` when a token is set.
- Produces (Go test helpers, used by every later web test): `authedClient(t, g) *http.Client` now adds the bearer header through a `RoundTripper`; `dialStream(t, g, query)` offers the two subprotocols.

Replace `authedClient` and `staticJar` first, so the rest of the suite runs
against the new contract:

```go
// bearer adds the gateway token to every request, the way the page does.
type bearer struct {
	token string
	next  http.RoundTripper
}

func (b bearer) RoundTrip(r *http.Request) (*http.Response, error) {
	r = r.Clone(r.Context())
	r.Header.Set("Authorization", "Bearer "+b.token)
	return b.next.RoundTrip(r)
}

func authedClient(t *testing.T, g *Gateway) *http.Client {
	t.Helper()
	req, err := http.NewRequestWithContext(t.Context(), http.MethodPost, g.URL()+"/api/auth",
		strings.NewReader(`{"token":"`+g.token()+`"}`))
	require.NoError(t, err)
```

```go
const (
	// streamProtocol is the subprotocol the stream speaks. The page offers
	// it together with the token entry, and the gateway selects it.
	streamProtocol = "crush.v1"
	// authProtocolPrefix carries the token on the WebSocket upgrade, where
	// a browser cannot set an Authorization header.
	authProtocolPrefix = "crush.auth."
)

// requestToken returns the token a request presents: the bearer header,
// or on a WebSocket upgrade the crush.auth subprotocol entry. A query
// string never carries it, so the token stays out of URLs and logs.
func requestToken(r *http.Request) string {
	if v, ok := strings.CutPrefix(r.Header.Get("Authorization"), "Bearer "); ok {
		return strings.TrimSpace(v)
	}
	if !strings.EqualFold(r.Header.Get("Upgrade"), "websocket") {
		return ""
	}
	for _, field := range r.Header.Values("Sec-WebSocket-Protocol") {
		for _, p := range strings.Split(field, ",") {
			if v, ok := strings.CutPrefix(strings.TrimSpace(p), authProtocolPrefix); ok {
				return v
			}
		}
	}
	return ""
}
```

```ts
// The gateway token for this tab. sessionStorage is isolated by origin,
// which carries the gateway's port, so another local server never sees
// it, and a reload keeps it. Storage can throw; memory is the fallback.
const KEY = 'crush-web-token';
let memory: string | null = null;

export function token(): string | null {
  if (memory !== null) return memory;
  try { memory = sessionStorage.getItem(KEY); } catch { memory = null; }
  return memory;
}

export function setToken(t: string): void {
  memory = t;
  try { sessionStorage.setItem(KEY, t); } catch { /* memory only */ }
}

export function forgetToken(): void {
  memory = null;
  try { sessionStorage.removeItem(KEY); } catch { /* nothing stored */ }
}
```

```go
func writeLaunchFile(parent, launchURL string) (*launchFile, error) {
	dir, err := os.MkdirTemp(parent, "crush-web-")

		return nil, fmt.Errorf("web: launch dir: %w", err)

	path := filepath.Join(dir, "launch.html")

		_ = os.RemoveAll(dir)
		return nil, fmt.Errorf("web: launch file: %w", err)
	}
	esc := html.EscapeString(launchURL)
	_, werr := fmt.Fprintf(f, launchHTML, esc, esc)
	cerr := f.Close()
	if err := cmp.Or(werr, cerr); err != nil {
		_ = os.RemoveAll(dir)
		return nil, fmt.Errorf("web: launch file: %w", err)
	}
	return &launchFile{dir: dir, path: path}, nil
}
```

**Interfaces:**
- Wire contract (browser):
  - Frame `secure_prompt`, payload `{"prompts": SecurePrompt[]}` (oldest first, empty array when none), published whenever the set changes. Snapshot field `secure_prompts` with the same array (omitted when empty).
  - `SecurePrompt`: `{"source": "pinentry"|"ssh", "id": string, "kind": "passphrase"|"pin"|"password"|"confirm"|"touch", "title": string, "message": string, "details"?: string[], "retry"?: string}`. It never carries a secret.
  - `POST /api/pinentry/answer` and `POST /api/ssh/answer`, body `{"id": string, "secret": string}` (at most 8 KiB body, secret at most 4096 bytes). The `secret` field is required for passphrase, PIN and password prompts (an empty string is a valid answer); the routes read nothing but the body, so a secret sent in a header never reaches a resolver. A confirm prompt ignores `secret` and answers `"yes"`, the TUI's confirm value. 204 on success. 400 `secret_in_url` when the request has a query string; 400 `bad_json`; 400 `missing_secret`; 400 `secret_too_long`; 409 `not_pending` when the id is not an open prompt of that source, or the resolver answered `false` (answered elsewhere, expired, or the server was unreachable); 409 `touch_not_answerable` for a touch prompt.
  - `POST /api/pinentry/cancel` and `POST /api/ssh/cancel`, body `{"id": string}`: 204, 409 `not_pending`.
  - Raw `pinentry_prompt_request`, `pinentry_prompt_notification`, `ssh_prompt_request` and `ssh_prompt_notification` frames are no longer forwarded to tabs.
- Produces (Go): `type SecurePrompt struct` (fields above); `func (p *pending) securePrompts() []SecurePrompt`; `func (p *pending) securePrompt(source, id string) (SecurePrompt, bool)`; `func (p *pending) forgetSecure(source, id string) bool`; `func (g *Gateway) publishSecurePrompts()` (reads the set and publishes it while holding `g.securePubMu`, so the last frame published always carries the current set); `const frameSecurePrompt = "secure_prompt"`.

```go
// Package logtest captures the default logger's output in tests, so a
// test can prove a secret never reached a log line.
package logtest

// Buffer collects log output written from several goroutines.
type Buffer struct {
	mu  sync.Mutex
	buf bytes.Buffer
}

func (b *Buffer) Write(p []byte) (int, error) {
	b.mu.Lock()
	defer b.mu.Unlock()
	return b.buf.Write(p)
}

func (b *Buffer) String() string {
	b.mu.Lock()
	defer b.mu.Unlock()
	return b.buf.String()
}

// Capture routes the default logger into a buffer at debug level for the
// rest of the test. Tests that call it must not run in parallel.
func Capture(t testing.TB) *Buffer {
	t.Helper()
	b := &Buffer{}
	prev := slog.Default()
	slog.SetDefault(slog.New(slog.NewTextHandler(b, &slog.HandlerOptions{Level: slog.LevelDebug})))
	t.Cleanup(func() { slog.SetDefault(prev) })
	return b
}
```

```go
// SecurePrompt is a GPG or SSH prompt waiting for an answer, as the
// browser shows it. It never carries a secret.
type SecurePrompt struct {
	Source  string   `json:"source"`
	ID      string   `json:"id"`
	Kind    string   `json:"kind"`
	Title   string   `json:"title"`
	Message string   `json:"message"`
	Details []string `json:"details,omitempty"`
	Retry   string   `json:"retry,omitempty"`
}

const (
	sourcePinentry = "pinentry"
	sourceSSH      = "ssh"
)

func fromPinentry(r pinentry.PromptRequest) SecurePrompt {
	title := "GPG passphrase"
	if r.Kind == pinentry.KindPIN {
		title = "Security key PIN"
	}
	return SecurePrompt{Source: sourcePinentry, ID: r.ID, Kind: string(r.Kind), Title: title,
		Message: r.Prompt, Details: r.Key.Lines(), Retry: r.Error}
}

func fromSSH(r sshaskpass.PromptRequest) SecurePrompt {
	r = sshaskpass.Describe(r)
	p := SecurePrompt{Source: sourceSSH, ID: r.ID, Kind: string(r.Kind),
		Title: cmp.Or(r.Title, "SSH"), Message: cmp.Or(r.Message, r.Prompt)}
	if r.KeyInfo != "" {
		p.Details = []string{r.KeyInfo}
	}
	return p
}
```

```go
const (
	maxSecretBody  = 8 << 10
	maxSecretBytes = 4096
)

func (g *Gateway) registerPromptRoutes(api *http.ServeMux) {
	g.route(api, "POST /api/pinentry/answer", g.handleSecureAnswer(sourcePinentry))
	g.route(api, "POST /api/pinentry/cancel", g.handleSecureCancel(sourcePinentry))
	g.route(api, "POST /api/ssh/answer", g.handleSecureAnswer(sourceSSH))
	g.route(api, "POST /api/ssh/cancel", g.handleSecureCancel(sourceSSH))
}

// handleSecureAnswer delivers a secret to the open prompt. The secret is
// read from the body only, is never logged, and no answer echoes it.
func (g *Gateway) handleSecureAnswer(source string) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		if r.URL.RawQuery != "" {
			writeError(w, http.StatusBadRequest, "secret_in_url", "secrets are accepted in the request body only")
			return
		}
		var body struct {
			ID     string  `json:"id"`
			Secret *string `json:"secret"`
		}
		if err := json.NewDecoder(http.MaxBytesReader(w, r.Body, maxSecretBody)).Decode(&body); err != nil {
			writeError(w, http.StatusBadRequest, "bad_json", "request body is not valid JSON")
			return
		}
		if body.Secret != nil && len(*body.Secret) > maxSecretBytes {
			writeError(w, http.StatusBadRequest, "secret_too_long", "the answer is too long")
			return
		}
		p, ok := g.pending.securePrompt(source, body.ID)
		if !ok {
			writeError(w, http.StatusConflict, "not_pending", "The prompt was already answered or has expired.")
			return
		}
		var secret string
		switch p.Kind {
		case string(sshaskpass.KindTouch):
			writeError(w, http.StatusConflict, "touch_not_answerable", "Touch the security key to continue.")
			return
		case string(sshaskpass.KindConfirm):
			secret = "yes"
		default:
			if body.Secret == nil {
				writeError(w, http.StatusBadRequest, "missing_secret", "the answer belongs in the request body")
				return
			}
			secret = *body.Secret
		}
		var resolved bool
		if source == sourcePinentry {
			resolved = g.ws.PinentryRespond(p.ID, secret)
		} else {
			resolved = g.ws.SSHRespond(p.ID, secret)
		}
		if !resolved {
			writeError(w, http.StatusConflict, "not_pending", "The prompt was already answered or has expired.")
			return
		}
		if g.pending.forgetSecure(source, p.ID) {
			g.publishSecurePrompts()
		}
		slog.Debug("Web secure prompt answered", "source", source, "id", p.ID)
		w.WriteHeader(http.StatusNoContent)
	}
}
```

```go
package signin

// Challenge is what the user does to finish a sign-in: type UserCode at
// VerificationURL (device flows) or open VerificationURL (browser flows).
// DeviceCode is the poll secret; it never leaves the process.
type Challenge struct {
	DeviceCode      string
	UserCode        string
	VerificationURL string
	ExpiresIn       int
	Interval        int
}

// Flow is one provider's OAuth sign-in.
type Flow interface {
	// Name is the provider name the dialogs show, such as "GitHub Copilot".
	Name() string
	// Start begins the sign-in and returns the first challenge.
	Start(ctx context.Context) (Challenge, error)
	// Wait blocks until the token arrives. A flow that falls back to
	// another method returns the next challenge to show instead; the
	// caller shows it and calls Wait again with it.
	Wait(ctx context.Context, c Challenge) (tok *oauth.Token, next *Challenge, err error)
	// CodeEntry reports whether the sign-in can finish with a code pasted
	// back from the authorization page.
	CodeEntry() bool
	// SubmitCode exchanges a pasted code or callback URL for a token.
	SubmitCode(ctx context.Context, code string) (*oauth.Token, error)
	// Close releases the callback listener of a browser flow.
	Close()
}

var (
	// ErrUnsupported means the provider signs in with an API key only.
	ErrUnsupported = errors.New("this provider signs in with an API key")
	// ErrNoBrowserFlow means a code was submitted with no browser flow running.
	ErrNoBrowserFlow = errors.New("no browser flow in progress")
)

// New returns the flow for a provider id: hyper, copilot, openai or xai.
func New(providerID string) (Flow, error)
func NewCopilot() Flow
func NewHyper() Flow
func NewOpenAI() Flow
func NewGrok() Flow
```

```go
// oauthFlow adapts a signin.Flow to OAuthProvider, so the dialog and the
// web gateway run the same sign-in code.
type oauthFlow struct {
	flow     signin.Flow
	minStart time.Duration

	mu     sync.Mutex
	cancel context.CancelFunc
}

func newOAuthFlow(f signin.Flow, minStart time.Duration) OAuthProvider {
	return &oauthFlow{flow: f, minStart: minStart}
}

func (m *oauthFlow) name() string { return m.flow.Name() }

func (m *oauthFlow) initiateAuth() tea.Msg {
	started := time.Now()
	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()
	c, err := m.flow.Start(ctx)
	if wait := m.minStart - time.Since(started); wait > 0 {
		time.Sleep(wait)
	}
	if err != nil {
		return ActionOAuthErrored{Error: err}
	}
	return initiateOAuthMsg(c)
}

func (m *oauthFlow) startPolling(deviceCode string, expiresIn int) tea.Cmd {
	return func() tea.Msg {
		ctx := m.newContext()
		tok, next, err := m.flow.Wait(ctx, signin.Challenge{DeviceCode: deviceCode, ExpiresIn: expiresIn})
		switch {
		case ctx.Err() != nil:
			return nil // Cancelled, don't report an error.
		case err != nil:
			return ActionOAuthErrored{Error: err}
		case next != nil:
			return initiateOAuthMsg(*next)
		}
		return ActionCompleteOAuth{Token: tok}
	}
}

func (m *oauthFlow) stopPolling() tea.Msg {
	m.mu.Lock()
	if m.cancel != nil {
		m.cancel()
	}
	m.mu.Unlock()
	m.flow.Close()
	return nil
}

func (m *oauthFlow) supportsCodeEntry() bool { return m.flow.CodeEntry() }

func (m *oauthFlow) submitCode(input string) tea.Cmd {
	return func() tea.Msg {
		ctx := m.newContext()
		tok, err := m.flow.SubmitCode(ctx, input)
		if err != nil {
			if ctx.Err() != nil {
				return nil
			}
			return ActionOAuthErrored{Error: err}
		}
		return ActionCompleteOAuth{Token: tok}
	}
}

// newContext replaces the cancel func under the lock: the dialog's
// commands run on their own goroutines.
func (m *oauthFlow) newContext() context.Context {
	ctx, cancel := context.WithCancel(context.Background())
	m.mu.Lock()
	m.cancel = cancel
	m.mu.Unlock()
	return ctx
}

func initiateOAuthMsg(c signin.Challenge) ActionInitiateOAuth {
	return ActionInitiateOAuth{
		DeviceCode: c.DeviceCode, UserCode: c.UserCode, VerificationURL: c.VerificationURL,
		ExpiresIn: c.ExpiresIn, Interval: c.Interval,
	}
}
```

### Task A6: OAuth sign-in routes and the `signin` frame (wire contract: browser)

The gateway runs one `signin.Flow` at a time (Task A4), the way the TUI
shows one OAuth dialog. Starting a flow answers the first challenge; the
browser shows the device code with a copy button, or a link that opens the
provider page in a new tab (an `<a target="_blank" rel="noopener
noreferrer">` the user clicks, so no popup blocker interferes, Task A10).
Progress reaches every tab as a `signin` frame. Cancel stops the flow and
frees a browser flow's callback listener. When the token arrives the
gateway saves it with `Workspace.SetProviderAPIKey(config.ScopeGlobal, id,
token)` (client mode proxies it, and the token travels to the server in the
same body the TUI sends), then applies the chosen model if any. The token
never enters a frame or an answer. Copilot first tries
`Workspace.ImportCopilot`, as the TUI's `handleSelectModel` does
(`internal/ui/model/ui.go`; the gateway's own `handleSelectModel` in
`api_models.go` does not). `ImportCopilot` takes no context and may make a
network call; the start handler accepts that, as the TUI does.

Provider errors can carry response bodies (`internal/oauth/grok/device.go`
embeds one), so no sign-in log line in this task carries an error value:
each logs the provider id and an error class from `signInErrorClass`.

```go
type signinRun struct {
	id     string
	flow   signin.Flow
	ctx    context.Context
	cancel context.CancelFunc
	model  *signinModel
	once   sync.Once
	mu     sync.Mutex
	state  SignInState
}
```

- `handleOAuthStart`: validate as the contract says; for Copilot when the
  target is not configured, `if _, ok := g.ws.ImportCopilot(); ok` record a
  `done` state with `imported: true`, apply the model, publish, answer 200
  without creating a flow. Otherwise, under `signinMu`, refuse with 503
  when `signinClosed`, stop the current run (`stopRunLocked(run,
  "cancelled")`: cancel its context, `flow.Close()`, publish its
  `cancelled` state), create the flow through `g.newSignInFlow(id)`, derive
  `ctx, cancel := context.WithCancel(g.ctx)`, release the lock, call
  `flow.Start` with a 30 s timeout derived from `ctx`, and on error close
  the flow and answer 409 or 502, logging
  `slog.Warn("Web sign-in did not start", "provider", id, "reason", signInErrorClass(err))`.
  On success build the `waiting` state (`kind` is `device` when
  `UserCode` is set, else `browser`; `expires_at` is
  `time.Now().Unix() + ExpiresIn` when positive; `code_entry` is
  `flow.CodeEntry()` for a browser challenge), then take `signinMu` again:
  if `signinClosed` was set meanwhile, close the flow and answer 503
  `shutting_down`; otherwise store the run and call `signinWG.Add(1)`
  while still holding the lock, release it, start
  `go g.waitSignIn(run, challenge)`, publish and answer the state. The
  `Add` under the lock after the `signinClosed` check is what lets

## Deviations from the spec (deliberate)

- **Cookie replaced by a header (spec 2.3).** The spec's cookie exchange is
  replaced by a bearer token kept in `sessionStorage` and a WebSocket
  subprotocol, as its own threat model asks. `POST /api/auth` stays as the
  token check. A second tab opened by typing the bare origin now needs a
  fresh link (`/web`); a reload keeps working.
- **Launch file on WSL.** The redirect file is opened through its
  `\\wsl.localhost` path; with no `wslpath` the link is shown and nothing
  is opened, rather than falling back to the token URL.
- **Theme.** The browser theme is its own two-value setting (Holodeck,
  Solid glass) and does not follow the TUI theme, because the spec 3.2
  tokens and the 3.11 contrast rules fix the palette.
- **Detach.** Read as "stop web mode from the browser". The TUI has no
  detach command to mirror.
- **Config routes.** `GET /api/config` returns the display settings and
  the Agent Teams flag only; `set` and `remove` accept the four display
  keys only (M3 ruling 5).
- **Sign-in route spelling.** Spec 2.6 lists `POST /auth/provider/key`,
  `POST /auth/provider/oauth/start` and `GET /auth/provider/oauth/status`;
  the plan adds `GET /auth/providers`, `POST .../oauth/cancel` and
  `POST .../oauth/code`, and the progress also travels as a `signin`
  frame.
- **Secure prompt frame.** The raw `pinentry_*` and `ssh_*` wire frames are
  replaced, for tabs only, by one `secure_prompt` frame with a
  browser-ready shape; the client/server SSE stream is unchanged.
- **Unpin is read-only.** Browsing another session never sends prompts to
  it; the deck offers to open it in the terminal instead.
- **Export writes a file.** As in the TUI, into the working directory; no
  browser download.
- **Terminal-only commands.** Notification style (it configures the
  terminal's desktop notifications; the browser uses toasts, M3 deviation)
  and Toggle Remote Control (the Discord bridge is owned by the TUI
  process and its session lifecycle) stay out of the palette.
- **First-run setup.** With no provider and no agent, sign-in from the
  browser saves the credential, but choosing the first model and starting
  the agent stays in the terminal's onboarding.

## Planner decisions for the lead

1. **Theme means a browser-only Holodeck variant** (`holodeck`, `solid`),
   not a mirror of the TUI theme. Recommendation: accept; the spec fixes
   the browser palette. Cost if wrong: a user who expects the TUI theme in
   the tab gets a second setting; mapping TUI themes later is a new task.
2. **Detach means "stop web mode from the browser"** (`POST /api/detach`,
   gateway shutdown, token dies, TUI keeps running). Recommendation:
   accept; the TUI has no detach to mirror. Cost if wrong: one route and
   one button to rename or remove.
3. **The cookie is removed, not kept as a fallback**; the token lives in
   `sessionStorage` and rides as `Authorization: Bearer`. Recommendation:
   accept; a fallback keeps the exact leak the threat model names. Cost if
   wrong: typing the bare origin in a new tab needs `/web` again, and a
   script injected into the page could read the token (CSP
   `default-src 'self'` stands between).
4. **The stream token rides in a subprotocol** (`crush.auth.<token>`)
   rather than a one-time ticket from a POST. Recommendation: accept; no
   server state and no extra round trip on reconnect. Cost if wrong: the
   token appears in a request header a local proxy could log (loopback
   only); a ticket route is an hour's work.
5. **The launch file is removed after the first successful auth and on
   shutdown; WSL goes through `wslpath -w`; no fallback to the token URL.**
   Recommendation: accept. Cost if wrong: a slow opener that loads after a
   pasted-link auth finds the file gone, and WSL users without `wslpath`
   paste the link.
6. **The clipboard and the TUI notification keep the token link.**
   Recommendation: accept; spec 2.2 needs a pasteable link. Cost if wrong:
   clipboard history still holds the token until crush exits (documented).
7. **Secure prompt answers keep the `bool` Workspace API**: in client mode
   an unreachable server reads as 409 `not_pending`. Recommendation:
   accept; the TUI uses the same bool. Cost if wrong: a lost server looks
   like "already answered" for one prompt.
8. **One `secure_prompt` gateway frame replaces the raw pinentry and SSH
   frames for tabs.** Recommendation: accept. Cost if wrong: none known;
   the SSE stream for client/server clients is unchanged.
9. **Touch prompts show a notice and are never answered by the tab** (the
   TUI auto-confirms them). Recommendation: accept. Cost if wrong: none
   while a TUI always runs beside the gateway.
10. **OAuth flows move to `internal/oauth/signin` and the TUI dialogs
    become adapters** (instead of the gateway duplicating about 200 lines).
    Recommendation: accept, with the rule that no TUI test changes. Cost if
    wrong: a TUI OAuth regression; the duplicate is the fallback.
11. **One sign-in flow per gateway; a second start cancels the first.**
    Recommendation: accept; the callback ports allow one browser flow
    anyway. Cost if wrong: two tabs can cancel each other's sign-in.
12. **The API key is verified and saved in one request** (the TUI uses two
    Enters). Recommendation: accept. Cost if wrong: none for the user; the
    request waits for the provider check.
13. **A rejected key's provider error text is never logged** (providers
    echo part of the key). Recommendation: accept. Cost if wrong: less
    detail when debugging a rejected key.
14. **First-run onboarding stays in the terminal.** Recommendation: accept.
    Cost if wrong: a browser-only first run is impossible until a later
    task.
15. **Visual settings live in `options.web_display` in the global config**,
    and the gateway publishes from its own copy. Recommendation: accept;
    browser storage resets every run with the random port. Cost if wrong:
    one config write per toggle and a schema addition.
16. **`GET /api/config` returns display and Agent Teams only.**
    Recommendation: accept (M3 ruling 5). Cost if wrong: later surfaces
    add fields one by one.
17. **Export writes the Markdown file into the working directory**, as the
    TUI does. Recommendation: accept for parity. Cost if wrong: users who
    expect a browser download get a toast with a path.
18. **Goal and loop go through the terminal** with the Discord message
    (`discord.AutomationCommandMsg`) and inherit its "TUI shows another
    session" refusal. Recommendation: accept; one implementation. Cost if
    wrong: the browser cannot set a goal on a session the TUI is not
    showing.
19. **Notification style and Remote Control stay terminal-only.**

20. **Docker MCP routes live under `/api/docker-mcp/`** so a server named

21. **Unpin is read-only browsing.** Recommendation: accept; prompting a

22. **The chronoline covers the shown session's tool calls from loaded

## Lead rulings on the planner decisions (2026-11-24)

All 28 planner decisions are accepted as recommended, with these refinements:

1. Decision 4 (stream subprotocol): the tab offers two subprotocols, `crush.v1` and `crush.auth.<token>`; the gateway selects `crush.v1` and never echoes the token-bearing value in its response. A test pins the selected protocol. Cost if wrong: a browser that rejects the handshake, caught by Playwright.
2. Decision 10 (shared sign-in flows): every existing TUI test passes unchanged; a TUI test that has to change stops the task for a lead ruling. Cost if wrong: a TUI OAuth regression.
3. Decision 19: Notification settings and Remote Control are dropped from the browser and listed in the M4b PR as terminal-only.
4. Decision 26: M4a (A1 to A13) ships first on branch crush/web-mode-m4. M4b gets a fresh worktree from main after M4a merges, with its own preflight. Cost if wrong: one extra review and merge cycle.
5. Decision 3 (cookie removed): the 401 page text tells the user to run `/web` again for a new tab, and the docs task says so. Cost if wrong: confusion when a user opens the bare origin in a new tab.
