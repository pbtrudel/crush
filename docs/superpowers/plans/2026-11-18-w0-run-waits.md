# `crush run` Waits for Its Session Tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the in-process `crush run` return only when its session and every run started from it are idle, instead of when the session's first turn ends (delivery item 4 of the measurement design).

**Architecture:** The Team service gains a snapshot of one Lead session's team (`Tree`) and a change channel (`Changed`), and stops showing a teammate as idle in the moment between taking its queued messages and starting its next turn. The coordinator gains `WaitForSessionTree`, which reads the tree and then sleeps on two change signals: the Team service's and a new one fired whenever a coordinator run returns. It never polls. `SessionTree.Idle` is the one place idleness is decided. `app.RunNonInteractive` runs the prompt and then the wait in the same goroutine, so the output loop keeps streaming and Ctrl-C still ends the command at once. Teammates of a headless run are auto-approved like their Lead, because once the command waits for them, a permission prompt nobody can answer would hang it.

**Tech Stack:** Go 1.27, `charm.land/fantasy` v0.45.5, testify `require`.

**Spec:** `docs/superpowers/specs/2026-11-17-measurement-design.md`, section 3.1 (The command ends when its session tree is idle), Evidence 9 (Delegated work), Failure behavior, Validation (the `crush run` bullet), Scope, Delivery item 4. Items 5 (`--json`, exit codes) and 6 (`--max-steps`, `--timeout`) build on this one and are not implemented here.

## Review Focus

1. A teammate that needs a permission. The command auto-approves only its own session, so today a teammate's prompt waits for an answer nobody gives until the teammate's 30-minute context ends. Once the command waits, that becomes a hang of `crush run`. Pinned in Task 2 by a test that a non-interactive coordinator approves a teammate session and an interactive one does not.
2. A teammate resumed by a queued message. `watch` takes the messages and marks the member inactive under the lock, then starts the next turn after releasing it (`internal/agentteam/team.go:781-809`), so for a moment the tree reads idle. Pinned in Task 1 by reading the tree from the completed-task hook, which runs exactly in that window.
3. A session continued with `--session` or `--continue` whose team has messages an earlier process never delivered. The wait must not hang on them. Pinned in Task 1 by reopening the Team from disk.
4. The first turn fails (a provider error) after starting a teammate. The teammate is still writing to the log, so the command waits, then returns the turn's error. Pinned in Task 4.
5. Ctrl-C during the wait. The wait returns at once with the context's error and the command keeps exiting 130. Pinned in Task 3 (the coordinator's wait) and Task 4 (the command's goroutine).

Another session's teammates share the workspace's Team and its single `lead` inbox. They must neither hold this command nor be counted as its reports; Task 1's first test pins that too.

```go
// TreeStatus is what the Team service knows about the team one Lead
// session started.
type TreeStatus struct {
	// Sessions are the sessions of the tree's teammates that have run.
	Sessions []string
	// Active counts the teammates running, being started or about to be
	// started again.
	Active int
	// UnreadByTeammates counts messages written by this process to the
	// tree's teammates that they have not received yet.
	UnreadByTeammates int
	// UnreadByLead counts messages from the tree's teammates, their reports
	// included, that the Lead has not read.
	UnreadByLead int
}

// Tree reports the state of the team that sessionID leads. The run command
// reads it to decide whether delegated work is still in flight.
func (s *Service) Tree(sessionID string) TreeStatus {
	s.mu.Lock()
	defer s.mu.Unlock()
	var tree TreeStatus
	members := make(map[string]bool)
	for _, member := range s.visibleMembersLocked(s.scopeLocked(leadName, sessionID)) {
		members[member.Name] = true
		if member.SessionID != "" {
			tree.Sessions = append(tree.Sessions, member.SessionID)
		}
		switch s.statusLocked(member.Name) {
		case StatusRunning, StatusProvisioning:
			tree.Active++
		}
	}
	for i, msg := range s.state.Messages {
		switch {
		case msg.Delivered:
		case members[msg.To] && i >= s.loaded:
			tree.UnreadByTeammates++
		case msg.To == leadName && members[msg.From]:
			tree.UnreadByLead++
		}
	}
	return tree
}

// Changed returns a channel that is closed at the next change to the
// roster, an inbox or the task board. Take it before reading the state it
// guards, so a change made after the read cannot be missed.
func (s *Service) Changed() <-chan struct{} {
	s.mu.Lock()
	defer s.mu.Unlock()
	return s.changes
}
```

```go
func (s *Service) startRun(ctx context.Context, member Member, prompt string) (MemberView, error) {
	s.mu.Lock()
	runner := s.runner
	if runner == nil {
		s.mu.Unlock()
```

```go
package agent

import (
```
```go
	"context"
	"sync"

	"github.com/charmbracelet/crush/internal/agentteam"
```

```go
// SessionTree is what a session and the runs started from it had in flight
// when it was read.
type SessionTree struct {
	// Busy is true while the session, or a teammate session in its tree,
	// runs a turn or has prompts queued.
	Busy bool
	// Team is what the Team service reports for the tree. It is zero when
	// Agent Teams is off.
	Team agentteam.TreeStatus
}

// Idle reports whether nothing in the tree is running or about to run. It
// is the one place the run command's wait is decided, so a limit on the
// tree belongs beside it.
func (t SessionTree) Idle() bool {
	return !t.Busy && t.Team.Active == 0 && t.Team.UnreadByTeammates == 0
}

// TreeWatcher is implemented by coordinators that can tell when a session's
// tree has gone idle.
type TreeWatcher interface {
	// WaitForSessionTree blocks until the tree of sessionID is idle and
	// returns what it left behind. It returns early with ctx's error.
	WaitForSessionTree(ctx context.Context, sessionID string) (SessionTree, error)
}

var _ TreeWatcher = (*coordinator)(nil)

// treeSignal wakes the callers waiting for a session tree to change. Each
// change closes the current channel and drops it, so a caller that took the
// channel before reading the tree cannot miss a change made after the read.
// The zero value is ready to use.
type treeSignal struct {
	mu sync.Mutex
	ch chan struct{}
}

// changed returns the channel the next change closes.
func (s *treeSignal) changed() <-chan struct{} {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.ch == nil {
		s.ch = make(chan struct{})
	}
	return s.ch
}

// notify wakes every caller holding the current channel.
func (s *treeSignal) notify() {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.ch != nil {
		close(s.ch)
		s.ch = nil
	}
}

// sessionTree reads what the tree of sessionID has in flight.
func (c *coordinator) sessionTree(sessionID string) SessionTree {
	var tree SessionTree
	if c.team != nil {
		tree.Team = c.team.Tree(sessionID)
	}
	for _, id := range append([]string{sessionID}, tree.Team.Sessions...) {
		if c.IsSessionBusy(id) || c.QueuedPrompts(id) > 0 {
			tree.Busy = true
			break
		}
	}
	return tree
}

// WaitForSessionTree implements TreeWatcher. A tree only becomes idle when a
// run returns or the Team service changes, and both signal, so the tree is
// read once per change instead of on a timer.
func (c *coordinator) WaitForSessionTree(ctx context.Context, sessionID string) (SessionTree, error) {
	for {
		// Take the channels before reading the tree, so a change that lands
		// between the read and the select still wakes the loop.
		runEnded := c.runEnded.changed()
		var teamChanged <-chan struct{}
		if c.team != nil {
			teamChanged = c.team.Changed()
		}
		tree := c.sessionTree(sessionID)
		if tree.Idle() {
			return tree, nil
		}
		select {
		case <-runEnded:
		case <-teamChanged:
		case <-ctx.Done():
			return tree, ctx.Err()
		}
	}
}
```

```go
package app

import (
	"context"
	"fmt"
	"log/slog"

	"charm.land/fantasy"

	"github.com/charmbracelet/crush/internal/agent"
)

// runResponse is what the non-interactive command learns from its run.
type runResponse struct {
	result *fantasy.AgentResult
	err    error
	// tree is what the session's tree left behind when the wait ended.
	tree agent.SessionTree
}

// runAndWait runs prompt on sessionID, then waits for the session's tree to
// go idle, so the command does not end while a teammate the run started is
// still working. The response carries the first run's outcome: a teammate's
// report does not wake the session. The wait ends early only when ctx is
// done, which is how a signal still stops the command at once.
func runAndWait(ctx context.Context, coordinator agent.Coordinator, sessionID, prompt string) runResponse {
	var response runResponse
	response.result, response.err = coordinator.Run(ctx, sessionID, prompt)
	if response.err != nil {
		response.err = fmt.Errorf("failed to start agent processing stream: %w", response.err)
	}
	watcher, ok := coordinator.(agent.TreeWatcher)
	if !ok {
		return response
	}
	tree, err := watcher.WaitForSessionTree(ctx, sessionID)
	response.tree = tree
	if err != nil {
		slog.Debug("Non-interactive: stopped waiting for the session tree", "session_id", sessionID, "error", err)
		return response
	}
	slog.Info("Session tree is idle", "session_id", sessionID, "undelivered_reports", tree.Team.UnreadByLead)
	return response
}
```

## Noticed, not changed here

- `crush run` builds two coordinators: `app.New` calls `InitCoderAgent` (`internal/app/app.go:255`) and `RunNonInteractive` calls `InitCoderAgentNonInteractive` (`:352`), which replaces the first without shutting it down. The first keeps its own Team service and its background-job watcher (`internal/agent/coordinator.go:353`), so a background job that finishes during the command can also wake the session on the first coordinator's agent, which the wait does not see.
- The Lead inbox is one address, `lead`, for every session in a workspace. A Team tool call in any Lead session drains reports meant for other sessions (`teamResponse` calls `DrainInbox(caller)`, `internal/agent/team_tools.go:116`). `TreeStatus.UnreadByLead` filters by sender, so the count is per session; delivery is not.
- A subagent started with the `agent` tool asks for permissions on its own session, which nothing in `crush run` approves, so a subagent that needs a prompt blocks the Lead's turn until its context ends. That predates this change. Teammates are approved here because the new wait would turn their prompt into a hang of the command.
- A background job started by a teammate wakes the teammate's session on the main agent (`deliverNotice` treats `team-` ids as top-level sessions). The wait counts that run through `IsSessionBusy`, but the run itself uses the Lead's agent.
