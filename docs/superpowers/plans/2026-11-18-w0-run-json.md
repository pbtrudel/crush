# `crush run --json` and Its Exit Codes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the in-process `crush run` a `--json` flag that prints one JSON object describing the run, computed from the session log the command just wrote, and ends the command with exit code 0, 2 or 3 by the run's turn-end stamp (delivery item 5 of the measurement design).

**Architecture:** `internal/app/run_json.go` turns the rows the command wrote in its session tree into the object (`summarizeRun`), reading the tree with one hand-written recursive query and the existing `message.Service.List` (`treeRows`). `internal/app/run_exit.go` maps the object's `reason` to an exit code and an `ExitError` that carries it; `Execute` in `internal/cmd/root.go` exits with that code. `RunNonInteractive` notes the rows already in the tree before the run, lets item 4's `runAndWait` run the prompt and wait for the tree, then prints the object instead of streaming text. With `CRUSH_CLIENT_SERVER=1` the flag is refused before anything starts.

**Tech Stack:** Go 1.27, `database/sql` with the project's SQLite drivers, cobra and fang, testify `require`.

**Spec:** `docs/superpowers/specs/2026-11-17-measurement-design.md`, section 3 (3.2 `--json`, 3.5 exit codes, the refusal of the flags against a server), Failure behavior, Validation (the `crush run` bullet), Scope, Alternatives 5, Delivery item 5. Item 4 (`docs/superpowers/plans/2026-11-18-w0-run-waits.md`) is merged before this work starts; item 6 (`--max-steps`, `--timeout`, the `step_limit` and `time_limit` reasons) comes after it and is not implemented here.

- Without `--json` the command keeps today's output and exit codes (0, 1, 130) exactly; Alternatives 5 of the spec. `ExitError` is returned only on the `--json` path.
- Once a run has started, `--json` prints its object whatever the outcome, signals included; when the command fails before a run starts it prints nothing on standard output and exits 1. A run has started when the session holds at least one row this command wrote (the prompt's user row). Without one, the run's own error is returned unchanged.
- The object is read from the session log, never from an event: the reason is the `turn_end` stamp (`message.Finish.TurnEnd`, `internal/message/content.go`), and every count comes from rows. The only figures from elsewhere are `duration_ms` (the clock), `cost` (the session row), `undelivered_reports` (`runResponse.tree.Team.UnreadByLead`) and `error` (`runResponse.err`).
- Which rows count: those in the session's tree whose ids were not in the tree when the run started. The tree is the session and every session whose parent chain leads to it (subagents, teammates, `agentic_fetch`), read with one hand-written recursive query, because `ListSessions` returns top-level sessions only.
- Which run decides `reason` and `text`: the session's last stamped run that a visible user row opened (the prompt, or its continuation after `context_guard` or `context_overflow`, whose opening row the harness writes visibly). A run opened by hidden rows only, such as a wake-up by a background job during the wait, counts in `tree.turn_ends` and the totals but never in `reason`: whether such a run lands before the command ends is a matter of timing (spec 3.1), and its `empty` must not become the command's reason. With no stamped run of the prompt the reason is `error`.
- Exit codes with `--json` (spec 3.5): 0 for `completed`; 2 for `empty`, `max_tokens`, `content_filter`, `tool_stop`, `loop_guard`, `repetition_guard`, `context_guard`, `context_overflow`, `compaction_blocked`; 3 for `canceled`, `request_timeout`, `provider_error`, `compaction_failed`, `error` and any value this build does not know; 1 for a failure before or outside a run; 130 for a signal, which wins over everything.
- Hooks for later items: item 6 adds `message.TurnEndStepLimit` and `message.TurnEndTimeLimit` to the code-2 case of `runExitCode` in `internal/app/run_exit.go`, the rule "a run in the tree that ended with `step_limit` or `time_limit` is the reason" in `summarizeRun` in `internal/app/run_json.go` (after the loop, before `return`), and its two flags to `refuseOnServer` in `internal/cmd/run.go`. The object's fields and `runSchema = 1` do not change.

## Review Focus

1. `crush run --continue --json` on a session an earlier command already used, with an earlier teammate: the earlier rows, stamps and cost must not leak into the object. Pinned in Task 5 by `TestRunJSONPrintsWhatTheCommandWrote` (an earlier `max_tokens` run and cost are left out).

4. A failure after the session is resolved but before the prompt reaches the log (no coder agent, a hook that refuses the prompt): nothing on standard output, exit 1, the error printed on standard error as today. Pinned in Task 5 by `TestRunJSONPrintsNothingWithoutARun`.
5. A newer build's turn-end value read by an older binary, or a stamp this build never writes: it must not exit 0. Pinned in Task 2 by the `not_yet_known` row of `TestRunExitCode`.

	}

package app

import (
	"context"
	"database/sql"
	"strings"

	"github.com/charmbracelet/crush/internal/message"
	"github.com/charmbracelet/crush/internal/version"
)

// runSchema numbers the object `crush run --json` prints. Within one schema
// number fields are only added.
const runSchema = 1

// runTokens sums the usage the steps recorded on their finish parts.
type runTokens struct {
	Input      int64 `json:"input"`
	CacheRead  int64 `json:"cache_read"`
	CacheWrite int64 `json:"cache_write"`
	Output     int64 `json:"output"`
}

// runCounts is what the steps of some sessions did during the command.
type runCounts struct {
	Steps     int       `json:"steps"`
	ToolCalls int       `json:"tool_calls"`
	Tokens    runTokens `json:"tokens"`
}

// add counts one assistant row, which is one step, and reports whether
// Crush estimated its usage.
func (c *runCounts) add(m message.Message) bool {
	c.Steps++
	c.ToolCalls += len(m.ToolCalls())
	finish := m.FinishPart()
	if finish == nil || finish.Usage == nil {
		return false
	}
	c.Tokens.Input += finish.Usage.InputTokens
	c.Tokens.CacheRead += finish.Usage.CacheReadTokens
	c.Tokens.CacheWrite += finish.Usage.CacheWriteTokens
	c.Tokens.Output += finish.Usage.OutputTokens
	return finish.Usage.Estimated
}

// runTree is the command's session and every session started from it.
type runTree struct {
	Sessions int `json:"sessions"`
	runCounts
	TurnEnds           map[message.TurnEnd]int `json:"turn_ends"`
	UndeliveredReports int                     `json:"undelivered_reports"`
}

// runResult is the object `crush run --json` prints (measurement design,
// 3.2).
type runResult struct {
	Schema     int             `json:"schema"`
	SessionID  string          `json:"session_id"`
	Reason     message.TurnEnd `json:"reason"`
	Text       string          `json:"text"`
	DurationMs int64           `json:"duration_ms"`
	Model      string          `json:"model"`
	Provider   string          `json:"provider"`
	Build      string          `json:"build"`
	Session    runCounts       `json:"session"`
	Tree       runTree         `json:"tree"`
	Estimated  bool            `json:"estimated"`
	Cost       float64         `json:"cost"`
	Error      string          `json:"error,omitempty"`
}

// summarizeRun builds the object from the rows the command wrote in the
// tree of sessionID, each session's rows in log order. The duration, the
// cost, the unread reports and the error are not in these rows; the caller
// sets them.
//
// The reason and the text are those of the session's last run that a
// visible user row opened: the prompt, or its continuation after a
// compaction. A run the harness opened with hidden rows only, such as a
// wake-up by a background job during the wait, counts in the tree but
// never decides the reason, so whether such a run happened to start before
// the command ended cannot change how the command ends. Without a stamped
// run of the prompt the reason is error.
func summarizeRun(sessionID string, rows []message.Message) runResult {
	result := runResult{
		Schema:    runSchema,
		SessionID: sessionID,
		Reason:    message.TurnEndError,
		Build:     version.BuildStamp(),
		Tree:      runTree{TurnEnds: map[message.TurnEnd]int{}},
	}
	sessions := map[string]bool{sessionID: true}
	// opened is true once a visible user row of the session started the
	// run that the next stamp ends.
	opened := false
	for _, m := range rows {
		sessions[m.SessionID] = true
		root := m.SessionID == sessionID
		switch m.Role {
		case message.User:
			if root && !m.Content().Hidden {
				opened = true
			}
			continue
		case message.Assistant:
		default:
			continue
		}
		if result.Tree.add(m) {
			result.Estimated = true
		}
		if root {
			result.Session.add(m)
		}
		finish := m.FinishPart()
		if finish == nil || finish.TurnEnd == "" {
			continue
		}
		result.Tree.TurnEnds[finish.TurnEnd]++
		if !root {
			continue
		}
		if opened {
			result.Reason = finish.TurnEnd
			result.Text = strings.TrimSpace(m.Content().Text)
			result.Model, result.Provider = m.Model, m.Provider
		}
		opened = false
	}
	result.Tree.Sessions = len(sessions)
	return result
}

// treeSessionsQuery lists a session and every session started from it.
// UNION skips a session already listed, so a parent cycle cannot loop.
const treeSessionsQuery = `WITH RECURSIVE tree(id) AS (
	SELECT ?
	UNION
	SELECT sessions.id FROM sessions JOIN tree ON sessions.parent_session_id = tree.id
)
SELECT id FROM tree`

// treeRows lists every row in the tree of sessionID, each session's rows
// in log order.
func treeRows(ctx context.Context, conn *sql.DB, messages message.Service, sessionID string) ([]message.Message, error) {
	rows, err := conn.QueryContext(ctx, treeSessionsQuery, sessionID)
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	var ids []string
	for rows.Next() {
		var id string
		if err := rows.Scan(&id); err != nil {
			return nil, err
		}
		ids = append(ids, id)
	}
	if err := rows.Err(); err != nil {
		return nil, err
	}
	var all []message.Message
	for _, id := range ids {
		msgs, err := messages.List(ctx, id)
		if err != nil {
			return nil, err
		}
		all = append(all, msgs...)
	}
	return all, nil
}

import (
	"testing"

	"github.com/stretchr/testify/require"

	"github.com/charmbracelet/crush/internal/message"

// Every turn-end value the agent stamps, with the exit code of its row in
// the measurement design's table (3.5).
func TestRunExitCode(t *testing.T) {
	t.Parallel()
	tests := []struct {
		reason message.TurnEnd
		want   int
	}{
		{message.TurnEndCompleted, 0},
		{message.TurnEndEmpty, 2},
		{message.TurnEndMaxTokens, 2},
		{message.TurnEndContentFilter, 2},
		{message.TurnEndToolStop, 2},
		{message.TurnEndLoopGuard, 2},
		{message.TurnEndRepetitionGuard, 2},
		{message.TurnEndContextGuard, 2},
		{message.TurnEndContextOverflow, 2},
		{message.TurnEndCompactionBlocked, 2},
		{message.TurnEndCanceled, 3},
		{message.TurnEndRequestTimeout, 3},
		{message.TurnEndProviderError, 3},
		{message.TurnEndCompactionFailed, 3},
		{message.TurnEndError, 3},
		// A value a newer build may write says nothing about the model.
		{message.TurnEnd("not_yet_known"), 3},
	}
	for _, tt := range tests {
		t.Run(string(tt.reason), func(t *testing.T) {
			t.Parallel()
			require.Equal(t, tt.want, runExitCode(tt.reason))
			err := runExitError(tt.reason)
			if tt.want == 0 {
				require.NoError(t, err)

package app

import (
	"fmt"

	"github.com/charmbracelet/crush/internal/message"
)

// ExitError ends `crush run --json` with Code. The object the command
// printed already says why, so the error is not printed again.
type ExitError struct {
	Code   int
	Reason message.TurnEnd
}

func (e *ExitError) Error() string {
	return fmt.Sprintf("the run ended with %s", e.Reason)
}

// runExitCode maps the reason of the command's run to the exit code of
// `crush run --json` (measurement design, 3.5): 0 when the model said it
// was done, 2 when the work can be graded but the model did not complete
// the turn, 3 when the outcome says nothing about the model. A reason this
// build does not know is 3.
func runExitCode(reason message.TurnEnd) int {
	switch reason {
	case message.TurnEndCompleted:
		return 0
	case message.TurnEndEmpty, message.TurnEndMaxTokens, message.TurnEndContentFilter,
		message.TurnEndToolStop, message.TurnEndLoopGuard, message.TurnEndRepetitionGuard,
		message.TurnEndContextGuard, message.TurnEndContextOverflow,
		message.TurnEndCompactionBlocked:
		return 2
	default:
		return 3
	}
}

// runExitError is what the command returns after printing its object: nil
// for a completed run, else the error that carries the exit code.
func runExitError(reason message.TurnEnd) error {
	code := runExitCode(reason)
	if code == 0 {
		return nil
	}
	return &ExitError{Code: code, Reason: reason}
}

package app

import (
	"cmp"
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"log/slog"
	"time"

	"github.com/charmbracelet/crush/internal/message"
	"github.com/charmbracelet/crush/internal/session"
)

// runSettleGrace bounds how long a signalled command waits for its run to
// record the cancel, so that the object it prints can report it.
const runSettleGrace = 5 * time.Second

// runStart is what the command knew before its run started.
type runStart struct {
	at   time.Time
	cost float64
	// written holds the rows already in the session's tree. The object
	// counts only the rows the command writes.
	written map[string]bool
}

// startRun notes the state of the session's tree before the run starts.
func (app *App) startRun(ctx context.Context, sess session.Session) (runStart, error) {
	rows, err := treeRows(ctx, app.conn, app.Messages, sess.ID)
	if err != nil {
		return runStart{}, err
	}
	start := runStart{at: time.Now(), cost: sess.Cost, written: make(map[string]bool, len(rows))}
	for _, row := range rows {
		start.written[row.ID] = true
	}
	return start, nil
}

// finishRunJSON waits for the run and its session tree, then prints the
// object. A signal stops the wait: the run is given a moment to record its
// cancel, and the process still exits 130.
func (app *App) finishRunJSON(ctx context.Context, output io.Writer, sessionID string, start runStart, done <-chan runResponse) error {
	var response runResponse
	select {
	case response = <-done:
	case <-ctx.Done():
		select {
		case response = <-done:
		case <-time.After(runSettleGrace):
			response.err = ctx.Err()
		}
	}
	return app.printRunJSON(context.WithoutCancel(ctx), output, sessionID, start, response)
}

// printRunJSON prints the object for the rows the command wrote and
// returns the error that carries the exit code. When the prompt never
// reached the log no run started: nothing is printed and the run's error is
// returned, so the command exits 1.
func (app *App) printRunJSON(ctx context.Context, output io.Writer, sessionID string, start runStart, response runResponse) error {
	if err := app.Messages.FlushAll(ctx); err != nil {
		slog.Warn("Failed to flush messages before reading the run", "error", err)
	}
	rows, err := treeRows(ctx, app.conn, app.Messages, sessionID)
	if err != nil {
		return fmt.Errorf("failed to read the run from the session log: %w", err)
	}
	var written []message.Message
	started := false
	for _, row := range rows {
		if start.written[row.ID] {
			continue
		}
		written = append(written, row)
		started = started || row.SessionID == sessionID
	}
	if !started {
		return cmp.Or(response.err, errors.New("the run wrote nothing to the session log"))
	}
	result := summarizeRun(sessionID, written)
	result.DurationMs = time.Since(start.at).Milliseconds()
	result.Tree.UndeliveredReports = response.tree.Team.UnreadByLead
	// The session's cost already includes what its child sessions cost.
	if sess, err := app.Sessions.Get(ctx, sessionID); err == nil {
		result.Cost = sess.Cost - start.cost
	}
	if response.err != nil {
		result.Error = response.err.Error()
	}
	encoder := json.NewEncoder(output)
	encoder.SetEscapeHTML(false)
	if err := encoder.Encode(result); err != nil {
		return fmt.Errorf("failed to print the run: %w", err)
	}
	return runExitError(result.Reason)
}
